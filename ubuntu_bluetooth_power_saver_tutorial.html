Ubuntu troubleshooting guide

Bluetooth Off + Power Saver at Every Startup

A practical, step-by-step record of the fix for Ubuntu 26.04.1 LTS on a Dell Inspiron 14 5418 using TLP 1.10.2.

Ubuntu 26.04.1 LTS TLP 1.10.2 Bluetooth disabled by default Power Saver on AC & battery
On this page 1. Problem and goal 2. Inspect the system 3. Configure TLP 4. Disable Bluetooth at startup 5. Apply the changes 6. Verify after reboot 7. Troubleshooting 8. Undo the Bluetooth service

1Problem and intended result

On this laptop, each fresh startup restored Bluetooth to On and selected Performance while connected to AC power, or Balanced while running on battery. The goal was to make the preferred state persist across shutdowns and restarts.

SettingDesired state
BluetoothOff (software-blocked) after startup
TLP power profilePower Saver on AC and battery
Firmware platform profilequiet
CPU energy-performance preferencepower
Important distinction: TLP's quiet platform profile is a firmware-level setting; it is not itself the same thing as the “Power Saver” label in GNOME Quick Settings. In this setup, tlpctl get is the check for the active TLP profile.

2Inspect the existing setup first

Before changing anything, identify which power manager is active. These commands are diagnostic and do not change settings.

lsb_release -ds

rfkill list bluetooth
systemctl is-enabled bluetooth.service
systemctl is-enabled systemd-rfkill.service 2>/dev/null

systemctl is-active tlp.service
systemctl is-active power-profiles-daemon.service
systemctl is-active tuned.service

sudo tlp-stat -p
command -v powerprofilesctl || echo "powerprofilesctl not installed"

dpkg -l | grep -E 'tlp|power-profiles-daemon|tuned'

On the system covered by this guide, the relevant findings were:

  • Ubuntu 26.04.1 LTS and TLP 1.10.2 were installed.
  • TLP was active; power-profiles-daemon and tuned were inactive.
  • tlp-pd was installed, providing the desktop integration for TLP power profiles.
  • The available firmware profiles were cool quiet balanced performance.
  • Initially, Bluetooth was unblocked and the firmware profile was performance.
Do not run two competing power managers. For this configuration, keep the existing TLP setup and its tlp-pd integration. Do not install or enable another power manager just to try to force the menu label.

3Configure TLP for Power Saver on AC and battery

Back up the TLP configuration file before editing it:

sudo cp /etc/tlp.conf /etc/tlp.conf.backup
sudo nano /etc/tlp.conf

In /etc/tlp.conf, edit existing entries if they are present. Do not leave duplicate active definitions. Set the following values:

TLP_PROFILE_AC=SAV
TLP_PROFILE_BAT=SAV

PLATFORM_PROFILE_ON_AC=quiet
PLATFORM_PROFILE_ON_BAT=quiet

CPU_ENERGY_PERF_POLICY_ON_AC=power
CPU_ENERGY_PERF_POLICY_ON_BAT=power

PLATFORM_PROFILE_ON_SAV=quiet
CPU_ENERGY_PERF_POLICY_ON_SAV=power

Save in Nano with Ctrl+O, press Enter, then exit with Ctrl+X.

What these options do: TLP_PROFILE_AC=SAV and TLP_PROFILE_BAT=SAV request TLP's Power Saver profile for both power sources. The platform-profile and CPU energy-preference options request lower-power settings. Actual hardware support and the GNOME label can vary.

Apply the configuration:

sudo tlp start
tlpctl get
sudo tlp-stat -p

The successful output in this case included:

TLP started using profile power-saver/SAV (auto).
power-saver

And in the platform section:

/sys/firmware/acpi/platform_profile = quiet

And in the processor section:

/sys/devices/system/cpu/cpu0/cpufreq/energy_performance_preference = power

4Make Bluetooth stay off at startup

The system initially reported Bluetooth as not blocked. A small systemd oneshot service was created to software-block Bluetooth during startup.

Create the service file:

sudo tee /etc/systemd/system/bluetooth-off.service > /dev/null <<'EOF'
[Unit]
Description=Block Bluetooth at startup
After=bluetooth.service

[Service]
Type=oneshot
ExecStart=/usr/sbin/rfkill block bluetooth
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

Reload systemd and enable/start the service:

sudo systemctl daemon-reload
sudo systemctl enable --now bluetooth-off.service
rfkill list bluetooth

Expected result:

Soft blocked: yes
Hard blocked: no
Meaning: “Soft blocked: yes” means Linux has disabled the Bluetooth radio in software. “Hard blocked: no” means no hardware switch or firmware hard block is reported. You can turn Bluetooth back on manually when you need it; this service applies the block at startup rather than continuously preventing manual use.

5Check the service and saved configuration

Confirm that the Bluetooth service is enabled and inspect the active TLP settings:

systemctl is-enabled bluetooth-off.service
systemctl status bluetooth-off.service --no-pager

sudo tlp-stat -c | grep -E 'TLP_PROFILE_|PLATFORM_PROFILE_ON_|CPU_ENERGY_PERF_POLICY_ON_'

tlpctl get
rfkill list bluetooth

The first command should return enabled. The TLP configuration should contain the requested values for AC and battery, and tlpctl get should return power-saver.

6Verify after a complete reboot

Restart the laptop. After logging back in, run:

tlpctl get
rfkill list bluetooth
sudo tlp-stat -p

For this laptop, the post-reboot output confirmed all three items:

power-saver

Soft blocked: yes
Hard blocked: no

/sys/firmware/acpi/platform_profile = quiet
/sys/devices/system/cpu/cpu0/cpufreq/energy_performance_preference = power
Verified on the documented system: TLP returned power-saver, Bluetooth remained software-blocked, the firmware platform profile was quiet, and the CPU energy preference was power after reboot.

For full verification, also inspect GNOME Quick Settings once with the charger connected and once on battery. If the menu label disagrees with tlpctl get, treat that as a separate desktop-integration issue; the terminal output alone does not prove which label GNOME displays.

7Troubleshooting notes

If Bluetooth is on after reboot

systemctl status bluetooth-off.service --no-pager
journalctl -u bluetooth-off.service -b --no-pager
rfkill list bluetooth

Check that the service is enabled and has no execution error. The service uses /usr/sbin/rfkill; if that executable is not present at that path on another installation, find its path with command -v rfkill and update ExecStart accordingly.

If the active TLP profile is not Power Saver

tlpctl get
sudo tlp-stat -s
sudo tlp-stat -c
systemctl status tlp.service --no-pager

Confirm the AC/BAT profile settings are saved and there are no duplicate active entries in /etc/tlp.conf. Check the current power source as well, since TLP automatically responds to AC/battery changes.

If the GNOME menu still says Performance or Balanced

Do not install a second power manager immediately. First capture the TLP status, package list, and what the GNOME menu shows. The system's TLP profile and the desktop's displayed label are related but are not identical measurements.

8Undo the Bluetooth startup service (optional)

If you later decide you no longer want the automatic Bluetooth block, disable and remove only the service created in this guide:

sudo systemctl disable --now bluetooth-off.service
sudo rm /etc/systemd/system/bluetooth-off.service
sudo systemctl daemon-reload
sudo systemctl reset-failed

That removes the custom startup action. It does not necessarily unblock Bluetooth immediately. To unblock it now, run:

sudo rfkill unblock bluetooth
rfkill list bluetooth

To restore the TLP configuration backup, first back up your current file, then restore the saved copy and reapply TLP:

sudo cp /etc/tlp.conf /etc/tlp.conf.before-restore
sudo cp /etc/tlp.conf.backup /etc/tlp.conf
sudo tlp start
Restoring the backup also restores any unrelated TLP settings that were in the backup. Review the file first if you made other changes after creating it.
